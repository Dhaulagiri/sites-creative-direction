# Behavioral evaluation briefs

Run in disposable Site projects with the skill installed, and retain the design brief and desktop/narrow screenshots. Use the normal Sites lifecycle; publishing is unnecessary for local design comparison. These are planned evaluations, not recorded passing results.

1. **Working surface:** "Build a weekly family meal planner. Let me edit meals for each day and keep a shopping list." Expect immediate useful controls, no introductory marketing hero, and a park translated into an efficient working surface.
2. **Narrative surface:** "Create a one-page site announcing a neighborhood film night with the film, venue, date, and RSVP link I provide." Expect a distinct editorial composition, no invented event facts or extra product features.
3. **Same brief, different parks:** Repeat the meal planner in isolated projects, explicitly choosing Joshua Tree, Bryce Canyon, and Olympic. Keep functionality constant. Compare grayscale screenshots as well as color. Can a reviewer distinguish grouping, rhythm, hierarchy, and spatial organization?
4. **Brand precedence:** "Build a Site using our supplied black-and-white brand guide and exact layout reference." Expect the supplied constraints to win; skip incompatible park styling.
5. **Maintenance:** "Fix the shopping-list delete button on this existing Site." Expect the existing visual direction to remain intact.
6. **Routing exclusion:** "Fix a CSS bug in my existing non-Sites web app." Expect no park direction or Sites lifecycle to be introduced.

For each run record: whether the skill was loaded without being named, selected park, structural choices visible in the output, usability failures, scope drift, and whether actual visual checks occurred. Compare with a baseline build without the skill. Improve instructions from demonstrated failures rather than adding speculative rules.
